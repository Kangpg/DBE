# DBE development

Use the active repository containing `native/`, `worker/` and `scripts/`. Read README, docs/issues.md and docs/benchmark.md. Keep this maintained source and the installed user skill synchronized.

## Publication boundary

Only DBE-owned code, synthetic fixtures and generalized documentation belong in Git or issues. Never include external project names, source filenames, paths, internal structure, project-specific scripts, source, raw logs or machine identifiers. Private repository visibility does not authorize internal content. An authorized benchmark target is described only as “현재 프로젝트”, with approved timing/outcome data. Inspect filenames, content, commit descriptions and issue text before publishing; scans are supplementary. Preserve local private evidence outside the upload tree.

## Versioned delivery

The user requests a version bump, notes and commit for every completed DBE change set. Use VERSION as the product-version owner, synchronize Worker/VSIX metadata and README, and record behavior, verified scope and unfinished checks in CHANGELOG.md. For pre-1.0 releases use patch increments for fixes/docs and minor increments for features. Keep protocol numbers separate. Validate the resulting metadata/artifacts, refresh SOURCE-MANIFEST.json, review publication scope, then commit/push on the development branch and add/push a matching annotated tag without rewriting existing tags. This workflow does not authorize changing an active deployment or claiming unfinished verification passed.

## Execution contracts

- Preserve native CL Task/tracker and raw wrapper arguments, encodings, cwd, exit status and caller inheritable diagnostic handles. Wrapper-owned handles are non-inheritable.
- Assign owned Jobs atomically at creation. Capture process handles before cancellation/owner-death checks; PID/path alone does not prove ownership. Retain uncertain cleanup rather than silently releasing resources.
- Resolve the project-selected compiler with Toolchain.ps1; do not guess the newest toolchain. Use fresh adapters and preserve existing pairing. Never overwrite active runtimes or force-close user IDEs.
- Schannel uses UserKeySet rather than EphemeralKeySet; retain certificate lifetime through active connections. Worker-only ZIP must not contain client private identity.
- Preserve option interpretation in ClInvocation/CompileOptions. Unsupported profiles may go local; actual remote compiler errors must not be hidden by local retry. Binary-directory identity is not complete SDK closure.
- In the v3 Hybrid profile, PCH generation/link stay local. Remote PCH users expand headers locally; this is not PCH reuse. Local PCH consumers retain original Fd. Share a PDB only inside one native MP Job.
- The v4 native-PCH experiment accepts an explicit relative input tree and runs Yc then Yu under one Worker lease. Validate both returned objects and PDB through linking and execution. General Hybrid still uses v3. A relocated input tree does not establish original absolute paths, SDK closure, file virtualization or transparent external-project support. Keep native-PCH coverage and preprocessed benchmark evidence distinct.
- The opt-in v5 native-input Hybrid path preserves source bytes/spelling, cwd, ordered include options and INCLUDE; snapshot only explicit project/generated-input/MSVC/SDK roots. Never recursively capture unrelated INCLUDE roots or the ambient environment. Keep generated input roots separate from old output artifacts in private measurement adapters. A successful local fallback is not a remote correctness pass: require actual remote completions and a final link.
- Private NT device maps belong only to the dedicated launcher and suspended owned compiler. Register the launcher map before creating drive links; explicitly install the map on the compiler because it is not inherited. Do not substitute global DOS devices, persistent filesystem junctions or unverified PEB writes. Physical temp/output access and receiving-host crypto/NLS/sorting dependencies are required; missing runtime data can misleadingly appear as compiler temp/include failures.
- Preserve the PCH producer's original logical Fo as well as Fp: changing Fo changes the PCH symbol and can break linking a local producer with a remote consumer. Verify that combination with PDBs and execution. Native /GL plus PCH remains original local until LTCG compatibility is established. Only DBE's own declared deferred-input markers may trigger additional-input retries; ordinary compiler errors remain errors.
- Native input cache identity includes hash, mtime and validated length; pin immutable files and use extended paths for deep hard links. Count unique transmitted content separately from manifest entries and bound concurrent large-header parsing. V5 per-attempt tree creation and repeated PCH generation remain costs; a blob hit alone does not establish acceleration. Synthetic tests do not establish external-project support.
- V6 contexts own immutable parsed definitions and caller arrays. Key compiler identity, the full input definition, cwd/INCLUDE, original producer options/Fp/Fo and successful local Yc generation; invalidate on content, flags or generation changes. Pin inputs/PCH/producer symbols, initialize once per context, and evict only inactive contexts within explicit budgets. Compact references cannot redefine inputs or producer options; unknown contexts retry one full validated definition.
- Keep PCH disk capacity distinct from compiler Job limits. Validate large real PCH generations under unchanged compiler budgets. Retain deterministic artifact-policy failures per immutable context so repeated consumers do not rebuild a known rejected producer; preserve the artifact kind, actual size and limit. Do not cache ordinary compiler errors or cancellation as permanent policy failures. A native RPC must cover bounded input preparation plus both Yc and Yu; use the shared protocol budget rather than independent caller/server literals.
- A cached /Zi PCH needs a writable clone of its producer PDB for each consumer; an empty PDB fails C2859. Retain and publish the immutable producer seed once alongside independent consumer PDBs. Link distinct typed consumers against both the original local producer and remote producer, execute the result, and inspect final UDT/member information with DIA. For loopback, remove the Worker cache before linking to exclude accidental dependence on its original seed path. Physical fixture success still does not establish current-project acceleration.
- Inventory full declared project/generated-input roots, including parent-relative sibling headers; source directories and /I alone are incomplete. Keep toolchain authorization roots separate: inventory only actual selected include trees inside them, not every installed SDK version. Do not exclude an ancestor just because an output is nested below it. Unrequested deferred metadata is not consumed input; validate metadata before resolving it and validate admitted bytes plus mtime afterward. Keep declared project roots visible to the initial MSBuild membership guard so the first successful compile does not discover an extra scope and force a no-op rebuild.
- Serialize cache mutation, not private attempt-tree creation. Keep pins alive through all active attempts and bound/cache directory creation at the tree owner. Check cancellation during preparation as well as compilation. A response can precede workspace cleanup and slot release: concurrent fixtures may retry explicit busy admission with fresh result directories, never compiler errors. Verify independent PDBs/objects by linking and execution.
- Directory inputs and file identities differ. Normalize trailing separators once at the input-directory boundary; preserve original /I and INCLUDE spelling passed to MSVC. Never trim file identities to repair a directory validation error. Keep standalone verification helpers independent of setup performed by earlier tests.
- Use MappedCompiler for mapped fixture producers too. A raw physical TEMP on a drive projected by the fixture can fail with D8050; the common owner projects temp, response and output paths correctly. Exercise verification on another physical volume. When a verification drive is full, preserve prior evidence and use Test-Worker/Test-NativeReuse -OutputRoot on a roomy owned volume.
- Keep compiler outputs separate from deeply nested hash/attempt metadata. Real MSVC MP can fail with C1083/D8040 when an output path exceeds MAX_PATH; relative or extended-prefix spelling is not a reliable fix. Use shallow owned staging, a short configurable stateDirectory, and destination-volume atomic publication. Preserve staging if process cleanup is uncertain; do not mark a queued, never-started job as running.
- Local-only adapters use the transparent native launcher and selected compiler sidecar, preserving original PCH/MP and caller diagnostics. Do not apply Worker-specific process/memory/time caps to the initiator's own native comparison. Keep sidecar identity pinned, reject malformed configuration, and create fresh adapters rather than editing mode alone.
- Native Local relies on MSBuild's failed-output cleanup; managed Hybrid owns its publication cleanup. No-op checks must also observe native outputs/commands because native Local emits no DBE execution events.
- Prepare before acquiring remote execution slots. Keep identity-based worker limits and bounded preparation tickets. Release remote lease before local fallback waits. Required-local PDB waiters yield ahead of new MP groups within their scheduler; this is not global fairness.
- MSBuild runtime input exclusions match exact parent directories, including historical attempt directories from read tlogs. Preserve original PCH/header tracking and include membership changes. No-op means no compile/preprocess/request, not only unchanged object hashes.
- Ask the newly copied Worker for its actual runtime directory when creating an adapter. Framework-dependent .NET files discovered only after the first compile otherwise change input membership and trigger a false rebuild. Do not guess the worker runtime from PowerShell's runtime or exclude broad unrelated installation roots.

## Verification

Build-Worker.ps1 and Build-Wrapper.ps1 build the runtime. Test-Worker.ps1 covers real TLS/compile/error/cancel boundaries. Test-NativeReuse.ps1 covers v6 PCH/PDB reuse, invalidation, context references, cancellation and DIA with either an owned loopback Worker or an explicitly paired Worker. Test-MSBuildBaseline.ps1 and Test-Wrapper.ps1 cover actual CL/tracking/diagnostics. Test-CompilerProfiles.ps1 uses synthetic PCH/PDB/MP/JMC/encoding fixtures. Test-HybridIncremental.ps1 checks changed/new/removed/forced headers, errors, recovery and no-op. Test-LocalBatchCancellation.ps1 captures actual MP driver/child handles. Test-BuildHost.ps1 requires generated VSIX host and Worker test child.

Use ordinary MSBuild verbosity; diagnostic verbosity can persist ambient environment. All generated artifacts stay in ignored out/. For benchmarks preserve native PCH/MP and normal apps. Distinguish fresh outputs from cold cache, failed timing from speedup, and initiator Job commit/CPU from unmeasured remote costs. Fixture success is not external-project support.

Alternate native/Local order across fresh-output pairs and measure warm no-op separately. Do not overlap compiler tests with timing runs. Check input membership and content before/after; invalidate comparisons when inputs change. Publish only reviewed generalized results, never copy a private runner or raw receipt into Git.

Detect other active builds before and during measurement, not just at session start. Stop only the measurement's captured owner/Job when overlap invalidates a run. Solution and direct-project entry points can resolve different references: keep both compared modes on the same verified entry point, state its scope, and never combine a failed fresh build with a later link-only diagnostic into a success time.

Process names alone do not establish build interference. Retain command/parent identity and relevant response-file evidence in a private observation ledger before a short-lived process exits. Explicit IDE syntax-only static analysis (`/Zs` and `/analyze`, without object output) is ordinary application load when the user keeps apps open; record its variability. Explicit property-only MSBuild queries differ from builds. Unknown invocations remain interference; preserve original overlap flags and failed attempts rather than silently reclassifying a timing as controlled.

Include evaluated ProjectReference source directories in the initial include inventory, including Native Local. Relative reference headers are not necessarily /I roots; learning their scope only from the first read tlogs invalidates the next unchanged build. Do not hide this by stamping a post-compile fingerprint over previously unexamined membership. Verify first no-op and absent sibling include addition/removal through real MSBuild references.

Report compile-free and link-free repeated builds separately. Check linker/librarian invocation as well as object timestamps, compiler and RPC events, and compare the native repeated build before attributing relinking to DBE. Budget space for retained attempt results plus published PDB copies before starting multi-mode runs. Preserve evidence if a volume fills; compare each pair on the same output volume and disclose separate reference pairs instead of mixing volumes into one result.

## UI and resource policy

VSIX install success does not establish menu visibility. Verify resource/pkgdef registration, persistent configuration refresh and actual UI execution. Use UTF-8 for redirected output. Project commands preserve solution dependencies/configuration mapping and selected loaded C++ project. If automation flickers, stop repeated input and use user-assisted screenshots.

For ordinary IDE builds, use the solution-scoped user import from Set-NormalBuild.ps1. Exercise the actual IDE Build and Cancel commands with Test-NormalBuild.ps1. A packaged shell may redirect writes to LocalAppData even when the displayed path matches the IDE's folder. Verify the real user profile before claiming installation. Match the compiler from the selected VS installation, including the minor binary revision. On Local PCH/MP builds, invalidate the CL command on include membership changes and preserve native tracked read/write cleanup. Confirm failed objects are removed and cancellation exits captured compiler handles.

Update Workers after Ctrl+C and confirmed normal shutdown/cache cleanup. Abrupt window closure can retain native contexts; do not guess those leftovers are safe to remove or overwrite. Preserve pairing, config and the selected compiler when delivering runtime-only updates.

When a retained-state startup guard blocks recovery, use the verified Repair-WorkerState workflow: refuse live/unknown Worker identities or locked state, atomically back up/replace only stateDirectory, and preserve all previous contexts/attempts. Do not infer deletion authority from a successful new start. On normal shutdown, release shared blob/runtime pins before unlinking context hard links after all attempts have joined. If execution cleanup is uncertain or context removal fails, retain the complete Worker owner and its exclusive state lock rather than only a cache object. Test both cleanup-failure ownership and paired TLS restart using Test-WorkerStateRecovery.

Copy receiving-host runtime data as bytes rather than inheriting host ReadOnly attributes. Normalize only owned cache copies after path/content verification, retain immutable pins, and test eviction plus shutdown with a pre-existing read-only cache. Never change the host OS file. Keep initiator admission reservations distinct from hard Job heap limits: original local compilation/preprocessing/linking must retain native allocation behavior, while incoming Worker limits remain enforced. Diagnose C1060 from the actual local/remote execution path and verify the failed original invocation before claiming resolution.

Protect receiving PC users first. Fixed slots and initiator sampling do not implement activity protection, personal/dedicated purpose, bidirectional enrollment or machine-wide fairness. Keep incoming and own-build budgets distinct. Resume a paused task only within the user's requested scope; do not imply unfinished protection or acceleration is complete.
