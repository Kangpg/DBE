# 현재 프로젝트 벤치마크

측정일: 2026-10-29. 대상은 **현재 프로젝트**로만 표시한다. 식별 정보, 원본 코드, 경로, 파일명, 내부 구조와 상세 로그는 저장소에 포함하지 않는다.

## 결과

| 실행 | 일반 로컬 | DBE | DBE 결과 |
|---|---:|---:|---|
| A | 274.247초, 성공 | 1,928.442초 | 링크 입장 대기로 중단 |
| B | 276.404초, 성공 | 264.930초 | 입장 대기 시간 초과로 실패 |
| C | 290.930초, 성공 | 716.662초 | C1083/D8040으로 실패 |

일반 로컬은 4분 34초~4분 51초에 성공했다. 최신 DBE는 11분 57초에 실패했다. **완료한 DBE 전체 빌드 시간이 없으므로 가속률을 계산하지 않는다.** B의 짧은 실패 시간을 성능 향상으로 해석하지 않는다.

## 조건과 한계

- 동일 MSVC Hostx64, 원래 PCH/MP 설정과 동일 빌드 구성. baseline을 DBE에 맞춰 제한하지 않았다.
- 일반 앱을 유지하고 별도 출력 디렉터리를 사용했다. 백그라운드 부하와 OS cache 상태는 완전히 통제하지 않았다.
- 기존 생성 입력을 사용하고 외부 부수 효과가 있는 build event는 측정에서 제외했다. 일상 빌드의 이벤트 범위와 다르다.
- 원격 Worker 두 대를 사용했다. 전체 성공, 실제 프로젝트의 반복 no-op 비교와 Worker CPU/메모리/실제 전송량 계측은 완료하지 못했다.
- 최종 오류는 staging 경로 처리와 Job 한도 등을 구분해 재현해야 한다. 원인은 아직 확정하지 않았다.

## 후속 검증

합성 fixture로 경로/오류/취소 회귀를 먼저 검증하고, 같은 PCH/MP 조건의 native 대 DBE Local 전용 처리량을 비교한다. 이후 전처리·대기·전송·원격 실행·링크 비용을 분리한다. 전체 성공 후 전체/무변경/소스 수정/헤더 수정 비교를 반복한다. 실패는 빠짐없이 기록한다.

사용자 요청으로 추가 성능 구현을 멈췄다. [열린 이슈](issues.md)를 통해 재개 순서를 관리한다.
